# CSA09 Java Assignment 3 – CO3 Implementation

> Replace the sample identity fields before submission. Each student must run the full project in their own repository.

## Requirements
- JDK 11 or newer (JDK 17 recommended)
- Windows CMD / PowerShell, macOS Terminal, or Linux shell
- Git and a GitHub account

## Repository layout
- `Task01` – ATM exception handling
- `Task02` – user-defined exceptions and exception chaining
- `Task03` – manual resource closing and try-with-resources
- `Task04` – Thread and Runnable life-cycle demonstration
- `Task05` – synchronized cinema seat booking
- `Task06` – bounded producer-consumer and deadlock prevention
- `Task07` – ExecutorService + Callable + Future result processor

## Compile and run (Windows CMD)
Run each command from the project root:
```bat
javac -d out Task01\ATM.java
java -cp out ATM 123456 1000
java -cp out ATM ABC 1000
java -cp out ATM 123456 7000

javac -d out Task02\StorageDemo.java
java -cp out StorageDemo

javac -d out Task03\SalesReport.java
java -cp out SalesReport

javac -d out Task04\ThreadStations.java
java -cp out ThreadStations

javac -d out Task05\SeatBooking.java
java -cp out SeatBooking

javac -d out Task06\TokenCounter.java Task06\DeadlockDemo.java
java -cp out TokenCounter
java -cp out DeadlockDemo

javac -d out Task07\ResultProcessor.java
java -cp out ResultProcessor
```
For PowerShell, the same `javac` and `java` commands work; use `;` to separate commands.

## Expected observations
- Task01: valid withdrawals are approved; malformed values, invalid amounts, insufficient balance and missing card-reader file are handled through distinct exception paths. The `finally` message always appears.
- Task02: `Saved answer01.pdf`, followed by the wrapped storage error and its original cause.
- Task03: both generated reports contain the same lines; the try-with-resources version closes resources even on exceptional exits.
- Task04: four stations finish in scheduler-dependent order; the final total prints after all joins.
- Task05: exactly 10 seats are sold because the check-and-update method is synchronized; `bookWithBlock()` provides the synchronized-block alternative.
- Task06: collected token sum is 210; wallet total remains 2000 with consistent lock ordering.
- Task07: by default 10,000 files are considered, with one corrupt file and one missing path; the remaining files succeed. Pass a smaller count such as `100` for a quick test. Pool timings vary by machine and run.
